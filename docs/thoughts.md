# 想你了

## 页面与行为

首页第四个模块及“我们”页进入 `/pages/thoughts/thoughts`。可筛选收到/发出、分页、查看原留言与回复，详情可回复、软删除自己的内容。最多100字，空内容为“想你了”。原留言删除后连同回复一起隐藏；不删除微信侧已经发出的通知。

五个主页面挂载未读组件，前台每15秒检查；隐藏时停止，旧响应按会话版本丢弃。每次进入前台会话，同一批未读至多提示一次。关闭保留未读；知道了只确认当前一条；列表、详情及日历只读面板按正文进入可见视口时标记对应收件内容；滚动到的内容继续同步，屏幕外内容不顺带标记。页内每5秒同步列表的已读状态。头像签名URL短期复用，避免轮询反复触发对象存储图片加载。

日历在当天记录、重要日子旁新增柔和紫色“互动”标记，月度统计包含可见留言及回复，并按各自实际发生日期标记。选中日记录下仍按原方式显示互动数量。展开只读面板查看当天留言和回复并同步对应阅读状态；操作跳转原记录模块。归属日期使用数据库运行的北京时间，与现有记录一致，跨午夜回复归入回复实际日期。

## 接口

全部通过令牌解析当前空间；客户端不能指定发送人、收件人或space_id。

| 接口 | 用途 |
|---|---|
| GET /api/thoughts | 根留言分页（beforeId）、all/sent/received筛选、focusId定位（回复自动定位原留言） |
| POST /api/thoughts | content、requestId、可选rootId；原子去重，回复仅限当前双方的原留言 |
| GET /api/thoughts/unread | 本人当前空间的未读，最多20条 |
| GET /api/thoughts/day?date=YYYY-MM-DD | 当天完整可见内容与收发数量，查询不自动标记 |
| PUT /api/thoughts/read | ids最多200条，只标记当前空间、本人收件内容 |
| DELETE /api/thoughts/{id} | 仅发送人软删除；根留言隐藏整组 |
| PUT /api/notifications/preferences | event和布尔enabled，只更新本人接收偏好 |

发送按空间行锁串行检查幂等编号和提醒冷却，在提交后由现有BackgroundTasks尝试微信推送。没有新队列或基础设施。单人每分钟最多5条作为防重复/误触保护，同方向10分钟内已占用推送槽（pending/accepted）时后续只记站内内容。进程退出可能留下pending；不自动重发，以免不确定结果导致重复通知或重复消耗；10分钟后不再占用冷却窗。

wx_status为pending、accepted、unavailable、failed、suppressed、skipped；accepted仅表示微信接口接受。正文不写日志。接收人关闭开关、无授权、缺模板或调用异常不影响站内保存。

## 数据库与上线顺序

新增 `thought_messages` 与 `notification_preferences`，见 [表目录](database-tables.md)。全新schema已包含。已有our_time先备份，然后明确选库执行：

```sh
mysql <连接参数> our_time < database/migrations/016_thoughts.sql
mysql <连接参数> our_time < database/table-guide.sql
```

016仅新增表，MySQL DDL自动提交，不可当作可回滚事务；不能用全新schema覆盖既有库，也不能重跑015。随后发布后端，再发布小程序。旧版前端可以继续使用原有饭桌提醒接口。

如需回退应用，可回退前后端版本并保留新增表与数据，不执行DROP。本地生成数据库说明使用 `python3 scripts/build_schema_docs.py`，包含catalog.json、table-guide.sql、database-tables.md及schema说明区。015仍只引用该历史阶段已经存在的表。

## 微信配置

后端使用以下配置项，实际值仅保存在服务器环境文件，不提交 Git：

```ini
WECHAT_THOUGHT_TEMPLATE_ID=
WECHAT_THOUGHT_USER_KEY=
WECHAT_THOUGHT_MESSAGE_KEY=
```

必须选择当前小程序类目下适用于实际场景的订阅模板，字段与该模板详情一致。当前已配置“每日问候提醒”的两个短文字字段，按顺序为问候语 `thing1`（发送者称呼）、今日问候内容 `thing2`（留言正文）。不要复用饭桌模板填充无关内容。未配置时前端显示原因，站内功能照常运行。sync-config.sh已支持新配置；使用现有同步方式更新服务器配置。

统一补充最多申请三类，每类由当前接收用户自己允许一次，满额或关闭类型不请求。上限10是项目预计账本上限，非微信官方余额；模板变更后的新模板不能借用旧模板余额。接收开关只控制本服务请求发送，不修改微信客户端的系统订阅授权。
