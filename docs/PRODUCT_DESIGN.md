# 两个人的小饭桌 · 产品设计

## 产品定位

“两个人的小饭桌”是仅供一对伴侣使用的私人电子菜单、点菜工具和吃饭记录。它只解决一件日常小事：轻松告诉对方今天想吃什么。产品不包含价格、支付、配送、库存或营销能力。

## 核心体验与原则

- 温馨但克制：奶油粉、白色、留白和自然文案，不做商业商城视觉。
- 两人协作：创建或加入同一个饭桌后，共享菜单和订单，收藏仍属于个人。
- 点菜优先：菜品信息服务于“想吃”，热量只做温和的家庭估算。
- 主流程可靠：外部通知和图片服务未配置时，登录、菜单和订单仍可独立工作。

## 用户流程

1. 首次打开使用 `wx.login` 登录，自定义昵称。
2. 创建“小饭桌”获得邀请码，或输入伴侣的邀请码加入；同一饭桌最多两人。
3. 在首页接受随机推荐，或在菜单按分类、关键词、标签找菜。
4. 收藏菜品或加入“今天的小菜单”，调整数量、餐次、日期和留言。
5. 提交后对方在小程序内收到未读提醒；如已授权并配置模板，也收到微信订阅消息。
6. 对方依次更新“收到啦 → 准备中 → 开饭啦 → 吃完啦”。
7. 完成订单进入“我们吃过”，可以一键“再吃一次”。

## 页面结构

底部四个 Tab：

- 首页：问候、日期、随机推荐、快捷分类、最近订单和不遮挡内容的菜单引导；主副标题由每张小饭桌独立设置。
- 菜单：接近常见在线点单的高效率布局；左侧纵向分类和对应已选数量，右侧大图菜品列表，显示系统统计的“点过次数”，支持搜索、收藏和加入小菜单；左侧底部固定“已选菜品 · 去提交”入口，点击进入完整小菜单提交页。
- 我们吃过：进行中订单与历史订单、状态流转、再次点菜。
- 我们：伴侣信息、统计、收藏、菜单管理、提醒和设置入口。

非 Tab 页面：绑定饭桌、菜品详情、今天的小菜单、订单详情、我的收藏、菜单管理、菜品编辑、分类管理、小饭桌设置。

## 数据结构

- `users`：微信 OpenID、昵称、头像、饭桌归属和未读数。
- `couples`：饭桌名称、一次性邀请码、到期时间、创建人、纪念日和首页主副标题。
- `starter_categories` / `starter_dishes`：只用于新饭桌首次初始化的示例菜单模板，不混入真实业务表。
- `categories` / `dishes`：按饭桌隔离的真实可编辑菜单，`couple_id` 强制非空。
- `dishes`：菜品、分类、图片、估算热量、时长、难度、辣度、标签和软下架。
- `favorites`：用户与菜品的个人收藏关系。
- `orders`：餐次、日期、留言、状态、目标用户、总估算热量和各阶段时间。
- `order_items`：包含菜名、图片、热量等不可变快照，保护历史记录。
- `notifications`：小程序内提醒、关联订单、已读时间。
- `meal_reviews`：为后续饭后评价和成品照片预留。

完整字段与索引见 `database/schema.sql`。

## API 结构

统一响应 `{ code, message, data }`，身份由 Bearer JWT 得出，业务查询必须带当前用户的 `couple_id`：

- `/api/auth`：微信登录、当前用户、资料更新。
- `/api/couples`：创建、加入、查看、更新、刷新邀请码和退出饭桌。
- `/api/categories`：饭桌分类列表、新增、编辑与安全下架。
- `/api/dishes`：检索、详情、增改、软下架、收藏。
- `/api/recommendations/today`：带收藏与近期食用权重的推荐。
- `/api/orders`：创建、列表、详情、状态流转、再次点菜。
- `/api/notifications`：未读列表、已读。
- `/api/uploads/cos-credential`：验证文件后签发 COS 临时凭证。

## 第一版功能

- 微信登录与自定义昵称。
- 两人饭桌创建/邀请码加入与数据隔离。
- 左侧分类点单布局、搜索、详情、热量、收藏和不可手改的历史点单次数。
- 今天的小菜单与本地持久化。
- 订单创建、六状态流转、历史和再次点菜。
- 首页规则推荐、最近订单和饭桌统计。
- 饭桌私有菜单首次由示例模板复制，全部菜品和分类均可新增、编辑、排序与软下架。
- 小饭桌名称、纪念日、首页文案、本人称呼与头像、成员查看、邀请码更新和退出管理。成员资料遵循本人可编辑、伴侣只读的边界；未上传头像时显示昵称首字。
- COS 安全直传框架、微信订阅消息框架及降级提示。
- Loading、空状态、错误重试、Toast 和统一占位图。

## 后续功能

- 饭后星级/文字评价和成品照片。
- 纪念日与饭饭日历。
- 依据库存食材、天气和口味的规则推荐。
- 饭桌数据导出和更细致的解绑/交接策略。
