## 已有功能与数据规则

- 微信登录 `wx.login → code2Session → JWT`，自定义昵称。
- 创建/加入饭桌，7 天邀请码、不区分大小写、同桌最多两人；稳定饭桌 UUID 与保留成员关联，能切换已加入饭桌。退出不自动删除数据；只有创建者且仅剩本人时可永久删除。
- 初始化菜单独立 `starter_categories/starter_dishes`，首次复制为饭桌私有菜单；业务分类/菜品 `couple_id` 非空。20 道初始菜品、10 分类均可编辑。
- 菜品新增/编辑/软下架 `enabled=0`、详情、估算热量、收藏、规则推荐；无热量隐藏，不显示 0 kcal。规则推荐考虑个人收藏和近期吃过，没有 AI 推荐。
- 点菜单本机持久化，数量/餐别/日期/留言；提交时后端重读菜品并计算热量、写订单快照，历史不被菜单改动污染。
- **最终用户流程是“提交 → 上菜即成功”**，去掉“接单/准备/吃完”按钮。`ready` 与旧 `completed` 都计入吃过/统计；旧状态保持兼容。提交/上菜成功明显短时提示并合理返回。
- 吃过按日期分组，支持双方评论、真实评论时间、本人删除评论、补上传成品照、再来一顿、二次确认删除。评论提交/退出清空草稿，不永久残留输入框。

## COS 与图片

- 腾讯云 COS 私有读写；服务端签 STS，小程序直接 PUT。永久凭证仅服务端；数据库保存 Object Key，响应按权限生成短时读 URL。
- Key 归属 `little-table/couples/<public-id>/...`；删饭桌清理前缀，菜品下架保留图片与历史快照；更换/删除图片时保护仍被历史引用的旧对象。头像旧图清理已修复。
- 原图最大 10MB，压缩上传不超 2MB；头像裁切 1:1/最大 640px，菜品及饭后照片裁切 4:3/最大 1280px。`wx.cropImage` 需基础库 2.26.0；列表方图用 aspectFill。
- 无图显示统一占位。生成照片是示例图，不能声称真实烹饪照片；用户允许逼真的家常风示例素材。
- 本地历史示例图 `assets/history-demo/` 对应记录 1、3、7，已上传并关联；番茄炒蛋/宫保鸡丁新图已替换，旧对象清理已验证。
- 排错重点：STS 签发成功不等于 PUT 上传成功；检查 **request 合法域名**、CORS PUT/Authorization/x-cos-security-token/Content-Type、STS 权限、签名时钟。失败通过 `/api/uploads/cos-failure` 上报，日志 `cos.client_upload_failed`；不要仅看 Nginx 或 `/health`。
